# WP-25 — golden portrait and quality regression

100 deterministic synthetic portraits, run through the real Retouch and
Geometry modules, measured against perceptual and structural thresholds. The
suite is the CI guardrail against “the algorithm got a little worse” and the
source of the visual diff artifact.

No photographs are stored here. `Corpus/portrait-corpus.json` is metadata only;
`GoldenSupport` draws every pixel from the description.

## What runs

```bash
# just the golden corpus + integration checks
swift test --filter StyleToneIntegrationTests

# everything CI runs
swift test
```

`StyleToneIntegrationTests` has four suites:

| suite | purpose |
|---|---|
| `PortraitCorpusTests` | 100-sample coverage matrix, renderer determinism, privacy, baseline/golden integrity |
| `PortraitQualityGateTests` | renders the 100 samples, runs retouch → geometry, evaluates ΔE00/SSIM/background/skin/edge metrics, applies aggregate gates |
| `PortraitFailureLocalizationTests` | injects a bent line, a skin cast and a blurred silhouette and proves the metrics and report fail on them |
| `PortraitSupportTests` (GoldenSupport) | unit-level renderer/metrics/report tests |

The pipeline is deliberately the production composition, not a mock:

```text
synthetic pixels + ground-truth analysis
  → SkinRetoucher (WP-07)
  → GeometryRenderingEngine
      FaceWarpContributor (WP-12)
      BodyWarpContributor (WP-13)
      LegsWarpContributor (WP-14)
      BackgroundWarpConstraint (WP-15), CPU backend
  → metrics
```

Ground-truth analysis (faces, body joints, person/skin/edge masks) is injected
instead of running Vision so the suite is deterministic across runners. Vision
detection accuracy is covered by the WP-05 suites; here the subject is whether
the pixels produced by the algorithm chain stay good.

**Evenness status.** The corpus runs with `evenness: 0.35`. The low-frequency
field is weighted by the validated skin alpha, so it cannot pull luma or chroma
from the background or hair outside the skin boundary. Evenness is also faded
out in a 2 px band around the silhouette, and the reconstructed skin is kept off
the 8-bit clipping rails. The baseline and the 12 visual goldens are re-recorded
for this setting; do not disable evenness or relax a threshold to hide a future
regression.

## Corpus

`Corpus/portrait-corpus.json` is generated by

```bash
python Tests/Integration/Tools/generate_portrait_corpus.py
python Tests/Integration/Tools/generate_portrait_corpus.py --check
```

Coverage of the 100 samples:

| dimension | coverage |
|---|---|
| skin tone I–VI | 17 / 17 / 17 / 17 / 16 / 16 |
| body types | slim 17, average 17, curvy 17, plus 17, tall 16, petite 16 |
| backgrounds | door-frame 20, floor-tiles 20, combined 20, window 15, table edge 15, plain 10 |
| framing | headshot 25, half-body 40, full-body 35 |
| people | 1 person 70, 2 people 20, 3 people 10 |
| occlusion | 45 samples: hair-over-face 10, arm-across-torso 10, hand-at-chin 8, object-in-front 8, scarf 5, loose sleeves 4 |

Every sample carries ground truth for:

- person / skin / background-structure masks (full resolution),
- face landmarks (contour, eyes, pupils, brows, nose, lips),
- body joints (neck, shoulders, elbows, wrists, hips, knees, ankles),
- straight background lines (door jambs, lintels, tile seams, window rails,
  table edges) with orientation and extent.

The renderer is in `Tests/GoldenSupport/Sources/GoldenSupport/PortraitRenderer.swift`.
It is pure Swift, filesystem-free and deterministic (seeded SplitMix-style
hashing). The scene is a cartoon studio portrait, not a synthetic photograph; it
is intentionally simple so a failure points at a metric or a pass, not at a
generative model.

## Metrics and thresholds

`PortraitMetricEvaluator` reports:

| area | metrics | acceptance |
|---|---|---|
| colour | ΔE00 on the retouched skin (mean/p95/max), mean ΔL/Δa/Δb, saturation ratio, hue shift, clipping increase | mean ≤ 3.0, p95 ≤ 6.0, \|ΔL\| ≤ 1.5, \|Δa\| ≤ 1.2, \|Δb\| ≤ 1.5, saturation 0.965–1.035, hue ≤ 3° |
| background | per-line pixel bend after warping: max deviation and best-fit angle | ≤ 1.5 px and ≤ 1.0° per line; < 5 % of measured samples may be distorted |
| skin safety | non-skin ΔE00 p95, final mean skin ΔL, dark-skin (V/VI) whitening, per-band fairness spread | non-skin p95 ≤ 1.5; final \|ΔL\| ≤ 1.2; V/VI ΔL ≤ 1.0; spread ≤ 1.0 |
| edges | silhouette contrast retention (median/mean), degraded/overshoot/sign-flip fractions, gradient-energy ratio | median ≥ 0.80, mean ≥ 0.82, degraded ≤ 5 %, overshoot ≤ 3 %, flips ≤ 1 %, gradient ratio ≥ 0.65 (bilinear resampling budget) |
| overall | sampled full-image ΔE00 (mean/p95), SSIM source vs output, compact 16×16 luma + 8×8 chroma signature | recorded and compared against the committed baseline |

The absolute thresholds come from perceptual/industry bands (ΔE00 2.5–3 is the
usual “visible difference” band, 1.5 px is one visible pixel at a 360 px-wide
preview). **Do not relax a threshold to make a sample pass; file the failure
against the owning module instead.**

## Quality gates

From the WP-25 card:

- obvious background distortion `< 5 %` of samples with measured lines;
- skin incidents `0` samples;
- silhouette/edge failures `0` samples;
- I–VI fairness spread and dark-skin whitening bounds;
- baseline regressions `0` in comparison mode.

A run fails the test when a gate fails or any sample exceeds a per-sample
threshold. The failure message names the sample, its category
(`tone/body framing background occlusion people`), the metric and the artifact
prefix. Diagnostics images are written for every failing sample.

## Baseline and visual goldens

The first green CI run is a **bootstrap** run:

1. `portrait-report.json/.md`, `contact-sheet.png` and
   `portrait-baseline-candidate.json` are written to the artifact directory.
2. Output candidates for the 12 representative samples in
   `PortraitGoldenSelection` are written to `golden-candidates/`.
3. The test passes only if every absolute gate passes (a candidate is not
   produced for a failing run).

To accept the run:

```bash
# download the golden-artifacts-<run-id> artifact from the Actions run
cp <artifact>/portrait-baseline-candidate.json Tests/Integration/Baselines/portrait-baseline.json
cp <artifact>/golden-candidates/*.png Tests/Integration/Goldens/
git add Tests/Integration/Baselines Tests/Integration/Goldens
```

The next run compares every sample's metrics/signature with the baseline and
the 12 outputs with the committed PNGs (`channelTolerance 1`, mean ΔE00 ≤ 1,
p95 ≤ 2, SSIM ≥ 0.99). When an algorithm change is intentional, re-record both
the baseline and the goldens with a review note in the PR.

Why not 100 golden PNGs? They would add megabytes and would still be synthetic
outputs, not a human reference. The baseline stores all 100 metric vectors plus
compact signatures, so spatial drift is covered for every sample; the 12 PNGs
make a representative diff directly reviewable. Every run attaches a 100-tile
contact sheet with source / output / amplified difference triplets.

The baseline and the 12 visual goldens were recorded from the green bootstrap
CI run
[40735868266](https://github.com/JHub-Wei/StyleTone/actions/runs/40735868266)

| gate | value | target |
|---|---|---|
| background distortion | **3.37 %** (3 of 89 measured samples, all warnings only) | < 5 % |
| skin incidents | **0** samples | 0 |
| silhouette/edge failures | **0** samples | 0 |
| I–VI fairness spread | **0.095 ΔL** | ≤ 1.0 |
| dark-skin mean ΔL (V/VI) | **0.103** | ≤ 1.0 |
| golden images | **12** recorded | — |
| pipeline time | 245 s for 100 × 360×480 frames | — |

The three background warnings are ps-051, ps-082 and ps-094 (table top and
floor horizon, 1.6–1.9 px deviation). They are reported in the artifact and by
the aggregate gate, which still passes because the card limits distortion to
`< 5 %` of samples, not to zero. Any increase that pushes the rate to 5 % blocks
the build.

`Baselines/portrait-baseline.json` stores per-sample metrics and signatures;
`Goldens/*.png` stores the 12 representative outputs. Re-record both together
when an algorithm change is intentional, and never raise a threshold to make a
new failure disappear.

## CI artifact

`.github/workflows/ios.yml` sets `ST_GOLDEN_ARTIFACTS_DIR` for `swift test` and
uploads it as `golden-artifacts-<run-id>` with `if: always()`. The local default
is `.build/golden-artifacts` (git-ignored). Files:

```text
portrait-report.json          machine-readable results, gates and metrics
portrait-report.md            CI summary tables and failure localization
contact-sheet.png             100 × (source | output | amplified diff)
ps-XXX-diagnostics.png        source / output / diff / overlay for failures
portrait-baseline-candidate.json  bootstrap only
golden-candidates/ps-XXX.png      bootstrap only
```

The XCTest attachments carry the same report/sheet/diagnostics inside the
`.xcresult` bundle.

## Authorized real-photo samples

Real photos stay outside version control, exactly as described in
`Fixtures/README.md`:

1. Owner drops files into `Fixtures/samples/` (git-ignored).
2. Owner adds a manifest entry with `license` and `authorizedBy`.
3. `PortraitCorpusTests.testAuthorizedSamplesAreOptionalAndNeverCommitted`
   decodes each file and checks its dimensions; CI has no files and skips it.

The automated 100-sample corpus is the CI gate. The manual 100-photo blind test
(`≥ 65 %`) and aesthetic review remain a human release-gate item; this suite
cannot judge aesthetics, skin realism or text legibility. See
`Packages/StyleToneGeometry/Background/ACCEPTANCE.md` for the photo-review
protocol.

## Privacy

- No network access, no upload, no photo decode in CI.
- Corpus JSON has no file names, licenses or paths; the only images committed
  are synthetic outputs under `Goldens/`.
- Artifacts contain synthetic pixels only. Logs contain sample ids and metrics,
  never a photo path or a file name.
- The full-corpus run is ~100 × 360×480 CPU frames; it is a regression gate, not
  a performance benchmark (`Tests/Performance` owns that).

## Limits

- Cartoon synthetic scenes do not predict real-photo aesthetics, hair rendering
  or optical blur. They catch geometric, colour and structural regressions.
- Ground-truth analysis bypasses Vision. If Vision output changes, the geometry
  tests still pass; the analysis suites cover that separately.
- Preview mesh (32×32) only; export quality is exercised by the module suites.
- The baseline is platform-dependent at the last bit. It is recorded on the
  macOS CI runner; re-record on a different runner architecture rather than
  widening tolerances.
