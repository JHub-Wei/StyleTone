- 文档版本：v3.0-confirmed
- 日期：2026-10-22
- 状态：**已确认**——中国优先 + 擦除 P1 + MVP 纯游客；账号/登录/微信全后置 v2.1；仅月付 ¥29.9；01–07 已按此重写

> **结论**：需要修改，而且不是“补两个功能”，是**重做产品定义与商业/合规边界**。v1.1 方案在“无账号、纯本地、只学影调色彩、不做形变/生成”的前提下是自洽的；但目标用户改为“年轻女性、人像精修、瘦脸瘦身瘦腿、风景擦除”后，这个前提不再成立。

> **后续最终确认（2026-10-22）**：MVP **纯游客、不做账号**；微信/手机号/Apple 全部随云擦除进入 v2.1；仅月付 ¥29.9；仅简体中文；工期 **24 周 / 250 PD**。本文第 5 节的登录分析作为 v2.1 预研保留，不代表 MVP 范围。

## 1. 为什么 v1.1 不再适用

| 维度 | v1.1 假设 | 新目标用户的实际需求 | 冲突程度 |
|---|---|---|---|
| 核心任务 | 把个人调色风格迁移到新照片 | 快速把人像修得自然好看：脸型、身材、腿、肤色、瑕疵、背景杂物 | 高 |
| 主要价值 | “像你自己修的” | “比原图更好看，但别太假” | 高 |
| 输入 | 15–25 组原图/成片配对 | 大多只想修 1 张；不愿先做 6 分钟校准 | 高 |
| 技术 | 参数化影调/色彩/轻人像 | 几何形变、分割、局部修复、生成式消除 | 高 |
| 隐私 | 照片完全不出设备 | 消除功能往往需要云端生成式模型 | 高 |
| 账号 | 无账号 | 跨设备、云端任务、订阅/额度、内容安全 | 高 |
| 市场 | 全球英语区软启动 | 中国年轻女性、小红书/抖音审美 | 高 |
| 周期 | 16 周 | 人像形变 + 中国合规，至少 24 周；含账号/云擦除 32–36 周 | 高 |

**判断**：v1.1 可以保留为“风格学习引擎”的技术底座，但产品层需要重新定位；不能把瘦脸瘦身、风景擦除当作 16 周 MVP 的附加项。

## 2. 建议的新定位

> **一句话**：**自然、可控、像你本人审美的 AI 人像精修。**
>
> 不是“网红同款滤镜”，也不是“换一张脸”；而是从你喜欢的原图/成片与少量选择中，学会你的肤色、磨皮、脸型/身材力度与整体影调，再用可调的工具完成修图。

### 2.1 目标用户修正

| 项目 | v1.1 | v2.0 |
|---|---|---|
| 核心人群 | 泛内容创作者/摄影爱好者 | 18–30 岁年轻女性，自拍/人像/旅行照，1–3 次/周发布 |
| 主要场景 | 主页风格统一、旅行回片 | 发朋友圈/小红书/抖音前的快速人像精修 |
| 核心痛点 | 每张重复调色 | 修得自然、快、不像模板；瘦脸瘦身不歪背景；消除路人/杂物 |
| 付费动机 | 节省调色时间 | 省时 + 好看 + 不被看出“P过” |
| 竞争 | Lightroom/VSCO | 美图秀秀、BeautyPlus、Ulike、Retouch、醒图、Snapseed |

### 2.2 三个产品支柱

1. **我的审美（个性化）**：不是从 15 组开始，而是 3/5/8 组配对（推荐 5 组）+ 6–8 次 A/B 选择，快速得到“我的精修偏好”：肤色、磨皮、脸型力度、身材力度、影调、颗粒。
2. **自然精修（核心）**：瘦脸、下颌/颧骨、瘦手臂/腰、瘦腿/拉长、磨皮、匀肤、去瑕疵、牙齿/眼睛轻微提亮；默认保守，强度可调，背景结构保护。
3. **擦除与清理（增值）**：路人、杂物、电线、文字；本地简单消除 + 云端复杂消除（单独授权）。这是**增值功能**，不建议作为首发唯一卖点。

### 2.3 仍然不做

- 换脸、身份替换、生成不存在的五官。
- 公开社区/作品广场。
- 专业图层/蒙版/印刷级校色。
- “颜值评分”“皮肤诊断”“美白/漂白”。
- 无提示的自动形变；所有形变默认需用户确认。

## 3. 范围与版本建议

### 3.1 推荐路径：人像优先，擦除后置

| 版本 | 范围 | 预计 | 说明 |
|---|---|---|---|
| **V2-MVP** | 游客可用；3/5/8 组快速校准；人像风格学习；瘦脸/下颌/瘦手臂/腰/腿/拉长；磨皮/匀肤/去瑕疵；本地导出；**无账号** | **24 周 / 250 PD** | 先把“自然好看 + 像我的审美”做出来；账号/擦除放 v2.1 |
| **V2.1** | 账号 + 微信/手机号/Apple + 参数同步 + 云端物体擦除 | +8–12 周 | 需要账号、云端 GPU、内容安全、隐私重构 |
| **V2.2** | 批量、多风格、牙齿/眼睛/黑眼圈、全球版、创作者风格包 | 更后 | 视留存与付费决定 |

### 3.2 如果“风景擦除”必须是首发

- 工期从 24 周增加到 **32–36 周**。
- 必须增加：账号体系、图片上传、GPU 推理、内容审核、云端存储与删除、数据跨境/本地化、生成式 AI 合规。
- “照片不出设备”必须改成“人像本地处理；擦除可选云端，单张授权、加密、自动删除”。
- 商业上需要额度/ credits，否则 GPU 成本不可控。

### 3.3 不建议的路径

- 在 16 周内同时做瘦脸瘦身、磨皮、消除、账号、订阅、全球合规。
- 先做“全能修图”，再找差异化；会直接进入美图/醒图的主战场。
- 用生成式模型做整个人像重绘；身份保真、审核、成本都不可控。

## 4. 技术影响

### 4.1 需要新增的引擎

| 模块 | 作用 | 技术 | 优先级 |
|---|---|---|---|
| Portrait Geometry | 瘦脸、下颌、颧骨、瘦手臂/腰、瘦腿、拉长 | Vision 人脸关键点 + 人体姿态 + 人体分割 + Metal 网格形变 | P0 |
| Skin Retouch | 磨皮、匀肤、去瑕疵、肤色 | 高频分离/导向滤波、局部修复、肤色蒙版 | P0 |
| Detail Retouch | 牙齿/眼睛轻微提亮、黑眼圈 | 关键点 + 局部颜色/亮度 | P1 |
| Object Erase | 路人/杂物/电线 | 端侧小模型或云端 inpainting | P1（或 P0，取决于决策） |
| Style Learner v2 | 从配对/选择学习肤色、磨皮、形变力度、影调 | 现有参数拟合 + 形变强度估计 | P0 |
| Account/Cloud | 登录、同步、云任务、额度 | BFF + Postgres + 对象存储 + GPU worker | P1（云消除时 P0） |

### 4.2 形变的技术边界

- **能做**：局部网格变形、边缘保护、背景直线保护、人脸/人体分割、预览实时。
- **难做**：多人、遮挡、手持物、复杂背景、紧身衣物纹理、头发边缘；需要大量真实样本测试。
- **不建议自动学习并直接应用**：从配对中估计“用户喜欢瘦多少”可以做默认值，但每次应用前必须让用户看到并确认；否则容易产生“被修丑/被冒犯”的体验与舆论风险。
- **身份保真**：形变只改轮廓，不重绘五官；输出仍应能认出是本人。

### 4.3 擦除的技术选择

| 方案 | 优点 | 缺点 | 建议 |
|---|---|---|---|
| 端侧小模型 inpainting | 隐私、无网、无 GPU 成本 | 模型大、质量有限、复杂场景差 | 简单物体/小面积可用；不建议作为首发核心 |
| 云端 inpainting（LaMa/扩散） | 质量好、迭代快 | 上传、成本、延迟、合规 | 若擦除是卖点，选云端；单张授权、自动删除 |
| 第三方 API | 上线快 | 数据流、成本、依赖、合规 | 可做早期验证，不建议长期核心 |

### 4.4 架构变化

```text
Guest 本地链路（默认）
相册 → 人像分析 → 风格参数 → 形变/磨皮 → 导出
   ↑ v2.1 账号：同步风格/订阅/云任务

云端链路（仅擦除，单独授权）
原图+蒙版 → 登录/额度 → 加密上传 → GPU inpainting
→ 内容安全 → 下载 → 24h 删除
```

新增后端：Auth、User、Entitlement、CloudJob、UploadAsset、CreditLedger、Moderation、Deletion。v1.1 的“只有配置 Worker”不再够用。

## 5. 登录与账号方案（v2.1 预研；MVP 不做）

> 本节用于 v2.1 账号 + 云擦除立项，**不是 MVP 范围**。MVP 纯游客、无登录、无后端。

### 5.1 先判断：是否真的需要登录

| 产品形态 | 是否需要账号 | 说明 |
|---|---|---|
| 纯本地修图 | 不需要 | StoreKit 可恢复订阅；风格存本机；登录只会增加摩擦 |
| 本地 + 云擦除 | **需要（或至少匿名账户 + 登录）** | 需要额度、任务归属、滥用控制、跨设备记录、删除 |
| 多设备同步 | 需要 | 风格/订阅/历史跨设备 |
| 公开社区/风格包 | 需要 | 内容安全、举报、封禁；不建议首发 |

**最终选择：MVP 纯游客，账号不做。** 本地人像功能直接可用；微信/手机号/Apple/同步随云擦除进入 v2.1。这样激活最快、合规最轻；代价是换机不保留风格。

### 5.2 登录方式对比

| 方式 | 全球可用 | 中国可用 | 成本/门槛 | 隐私/审核 | 建议 |
|---|---|---|---|---|---|
| **Sign in with Apple** | 是 | 是 | 低；需 Apple 开发者配置 | 隐私友好；第三方登录时通常必须提供 | **全球主登录；中国也保留** |
| **邮箱魔法链接** | 是 | 是 | 低；需邮件服务 | 需验证邮箱；无密码 | 全球次选；适合不想用 Apple 的用户 |
| **手机号 OTP** | 是（需 SMS 供应商） | 是（需国内短信资质/模板） | 中；短信费、欺诈/撞库、送达率 | 手机号是个人信息；需隐私政策、频控 | 中国主选之一；全球可选，不作唯一 |
| **微信登录** | 技术可行，实际中国为主 | 是 | 高；中国主体、开放平台审核、SDK、服务端换 token | 腾讯 SDK 数据流；PIPL；Apple 4.8 | **仅中国版；全球版不建议** |
| Google/Facebook | 是 | 不稳定/不必要 | 中；多 SDK、追踪争议 | Apple 4.8、隐私标签 | 不做 |

### 5.3 微信登录的真实门槛

不是“接个 SDK”那么简单：

1. **主体资质**：通常需要中国境内企业/个体工商户与微信开放平台开发者资质；个人开发者能力有限，以微信最新政策为准。
2. **应用审核**：创建移动应用、填写包名/Bundle ID、应用签名、官网/隐私政策，提交审核。
3. **SDK 集成**：微信 OpenSDK、Universal Links、URL Scheme、回调处理；服务端用 AppSecret 换 `access_token`/`openid`/`unionid`，**AppSecret 绝不能放客户端**。
4. **账号体系**：微信登录不直接给手机号；需要绑定手机号用于找回/合规，或设计无手机号的账号恢复。
5. **Apple 规则**：使用微信等第三方登录时，必须同时提供 Sign in with Apple 或等价的隐私友好登录（App Store 4.8）。
6. **隐私合规**：微信 SDK 会处理设备/网络/头像昵称等信息；需要隐私政策、第三方 SDK 清单、PIPL 告知同意。
7. **全球版冲突**：全球版“不接国内 SDK”与“接微信登录”直接矛盾；微信登录在海外用户中覆盖率也低。**不要把微信 SDK 塞进全球版**。

**结论**：微信登录只放中国版；全球版用 Apple + 邮箱（可选手机号）。

### 5.4 手机号登录的真实门槛

- 全球：Twilio/MessageBird 等 SMS 供应商；按条计费；需要防刷、频控、验证码有效期、失败重试。
- 中国：短信服务需要企业资质、签名/模板审核；手机号是个人信息，需单独告知；不建议把手机号作为唯一登录方式。
- 手机号登录可与微信绑定，作为账号恢复与跨设备手段。
- 若只做本地修图，手机号登录是纯增摩擦，不建议。

### 5.5 推荐方案

| 版本 | 登录方式 | 是否强制 | 说明 |
|---|---|---|---|
| 全球版 | Sign in with Apple + 邮箱魔法链接（可选手机号） | 否，云端功能时才要求 | 无微信/国内 SDK；GDPR/CCPA 友好 |
| 中国版 | 微信 + 手机号 + Sign in with Apple | 否，云端功能时才要求 | 独立构建/主体/备案；微信 SDK 仅中国版 |
| 游客 | 匿名本地账户 | — | 本地编辑、订阅恢复可用；云功能提示登录 |

**不要**在首次启动就弹登录框。年轻女性用户对“先登录才能看效果”非常敏感；先让她看到一张修好的自己，再在保存/云擦除/同步时登录。

### 5.6 账号数据模型（最小）

```text
User(id, created_at, status, region, deletion_requested_at)
Identity(id, user_id, provider[apple|email|phone|wechat], subject, created_at)
Profile(user_id, display_name?, locale, consent_version)
Entitlement(user_id, product_id, status, expires_at, source)
StyleProfile(id, user_id?, local_id, params, visibility[local|cloud])
CloudJob(id, user_id, type[erase], status, input_key, output_key, expires_at)
CreditLedger(user_id, delta, reason, created_at)
Consent(user_id, type, version, granted_at)
```

- 账号删除：App 内入口 + 服务端软删/硬删策略；订阅需在 Apple ID 取消，App 删除账号不自动退款。
- 数据导出：至少支持导出风格参数/购买记录；照片默认不长期保存。
- 云任务：24 小时内删除原图/结果；除非用户主动保存到相册。
- 内容安全：擦除功能需要禁止违法/色情/未成年人性化内容；保留审核与封禁机制。

## 6. 合规与伦理影响

### 6.1 新增风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 身体形象/容貌焦虑 | 瘦脸瘦身产品易被批评制造焦虑 | 默认自然、强度可控、不做“丑/胖”对比、不做颜值评分、提供关闭 |
| 未成年人 | 年轻女性中包含未成年人 | 年龄分级/提示；不主动面向未成年人；云功能年龄门槛评估 |
| 生成式 AI | 擦除可能构成深度合成/生成式服务 | 中国：评估备案/标识/安全评估；欧盟：AI Act 透明度；美国：州法 |
| 人脸数据 | 云上传人脸照片涉及生物识别/敏感信息 | 本地优先；云端单张同意；不建人脸模板；DPIA/BIPA 评估 |
| 微信 SDK | 数据流/跨境/隐私标签 | 仅中国版；PIPL 告知；SDK 清单 |
| 账号 | 删除、导出、跨境 | 5.1.1(v)、GDPR、PIPL；账号删除入口 |
| 云成本/滥用 | 免费额度被刷 | 登录、额度、频控、内容审核；不做设备指纹 |

### 6.2 市场选择

- **如果核心是“中国年轻女性”**：建议**中国优先**；MVP 纯游客，v2.1 再加微信/手机号/Apple、国内云、App 备案、PIPL；小红书/抖音获客。全球版后置。
- **如果团队/资源更适合全球**：目标应改为全球创作者，Apple/邮箱登录，不做微信；中国版后置。
- **不要**同时用“全球版无国内 SDK”和“微信登录服务中国年轻女性”作为同一版本策略；这是两个产品/两个合规体系。

## 7. 工期与团队重估

| 方案 | 范围 | 工期 | 团队 | 风险 |
|---|---|---|---|---|
| A（已确认） | 本地人像风格 + 形变 + 磨皮/去瑕疵；无账号/无后端 | **24 周 / 250 PD** | 3 iOS/图像 + 1 设计 + 0.5 QA | 形变质量/肤色/性能 |
| B | A + 账号 + 云端擦除 + 额度 | **32–36 周** | A + 0.5 后端/GPU/安全 | 云成本/合规/隐私 |

**结论**：从 16 周增加到 **24 周 / 250 PD**（含 QA、中国合规与发布缓冲）；如果追加账号+云擦除，增加到 **32–36 周**（在 24 周基础上 +8–12 周）。不要用原 160 人日覆盖新范围。

| # | 决策 | 选项 | 确认结果 |
|---|---|---|---|
| D1 | 首发市场 | 中国优先 / 全球优先 / 双版本 | **中国优先** |
| D2 | 擦除是否首发 | P0 云擦除 / P1 后置 / 只做本地简单消除 | **P1 后置** |
| D3 | 登录是否强制 | 游客优先、云端再登录 / 首次强制登录 | **MVP 纯游客，不做账号；账号/登录 v2.1** |
