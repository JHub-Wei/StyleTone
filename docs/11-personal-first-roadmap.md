# 11 · 自用优先路线：自用 → 朋友 TestFlight → App Store

- 文档版本：v1.0
- 日期：2026-10-24
- 状态：交付策略修订，核心产品/技术架构不变
- 关联：[README](../README.md) · [产品需求](01-product-requirements.md) · [技术架构](02-technical-architecture.md) · [开发计划](03-delivery-plan.md) · [任务分解](10-task-decomposition/README.md)

> **结论**：开发目的从“直接做商业化 MVP”改成“先自用、朋友试用、验证后再商业化”后，**核心算法、iOS 架构、人像工具范围不变**，但交付策略要大改：先砍掉订阅、付费墙、App Store 素材、App 备案、完整 onboarding 与商业级 QA；把第一个可用版本从约 24 周提前到约 **16–18 周**。商业化阶段再补 6–8 周。
>
> **重要**：自用版必须保留核心闭环——**导入原图/成片 → 学习风格 → 生成新成片**。不能退化成“只有手动滑杆的美颜工具”；否则验证的不是这个产品。

---

## 1. 总体判断

| 维度 | 是否改变 | 说明 |
|---|---|---|
| 核心技术 | **不变** | Vision/Metal/本地处理/形变/皮肤/风格学习仍是核心 |
| 产品定位 | 不变 | 自然、可控、像本人审美的人像精修 |
| MVP 功能 | **部分后置** | 先做手动工具+本地默认；配对学习/onboarding 后置到朋友阶段 |
| 账号/云 | 不变 | 自用/朋友阶段也不需要账号/云；纯本地 |
| 订阅/付费墙 | **后置到商业化** | 自用/朋友免费；不在前期做 StoreKit/定价 |
| App Store/备案 | **后置到商业化** | 自用/朋友用 TestFlight；不需要公开上架材料 |
| 完整 QA/无障碍/多设备 | **后置/缩减** | 先自己的机型+少量朋友机型；商业级 QA 后补 |
| 工期 | **改变** | 首个可用版 16–18 周；商业化总计约 26–31 周 |
| 风险 | **改变** | 从“上线风险”转为“自用是否真的好用、朋友是否愿意持续用” |

## 2. 三阶段路线

### Phase A：自用版（Self-use）

**目标**：你自己能稳定修人像，替代重复的手动 P 图流程。

| 项目 | 内容 |
|---|---|
| 时间 | **16–18 周**（3 名工程 + 设计/QA 兼职） |
| 工作量 | 约 **202 PD**（Lite QA 可压到 ~185） |
| 分发 | Xcode 直接装到自己的 iPhone；建议付费 Apple Developer（$99/年） |
| 账号 | 无 |
| 订阅 | 无；免费自用 |
| 网络 | 无业务后端；照片/参数全本地 |
| 设备 | 你的 iPhone 为主（iOS 17+） |
| 成功标准 | 你每周至少 3 次用它修图；单张 ≤5 分钟；背景不明显歪；肤色自然；**学到的风格能迁移到新图**；愿意把成片发出去 |

**Phase A 功能（只做这些）**
- **配对导入 + 质量检查**：3–5 组原图/成片；至少 3 组可学习。
- **风格学习**：肤色、磨皮、脸型/身材力度、影调；3 组试用、5 组标准、8 组稳定。
- **生成新成片**：导入新原图 → 应用学到的风格 → 手动微调 → 导出。
- 瘦脸/下颌、瘦手臂/腰、瘦腿/拉长。
- 磨皮/匀肤、点选去瑕疵、影调/色彩/颗粒。
- 背景保护、自然档、前后对比、20 步撤销。
- “我的默认”可保存，但**不是核心**；核心是配对学习。
- 简单设置/删除本地数据。
- 不做：订阅、付费墙、账号、微信/手机号、云擦除、批量、多风格、完整 onboarding、App Store 素材、App 备案。

### Phase B：朋友 TestFlight（Friends Beta）

**目标**：验证别人是否也觉得“自然、像自己、愿意持续用”。

| 项目 | 内容 |
|---|---|
| 时间 | **4–5 周** |
| 工作量 | 约 **22 PD** |
| 分发 | TestFlight 内测（建议 10–30 位朋友；内部测试员无需 Beta App Review；外部测试员需 Beta Review） |
| 账号 | 仍无 |
| 订阅 | 仍无；朋友免费 |
| 商业素材 | 不需要公开 App Store 页面；TestFlight 只需测试信息 |
| 成功标准 | 朋友每周至少 2 次使用；≥50% 成片无需再大改；≥5 人主动问“能不能一直用/愿意付费” |

**Phase B 新增**
- 风格卡：让朋友知道“学到了什么”、置信度、推荐力度。
- 简单引导/示范/空状态。
- TestFlight 反馈表、崩溃日志、使用访谈（不接第三方分析 SDK）。
- 根据朋友反馈微调配对/学习参数，但**核心闭环已在 Phase A**。

**Phase B 不做**：订阅、App Store 上架、正式隐私标签、App 备案、公开运营。

### Phase C：App Store 商业化

**目标**：验证付费意愿，正式上架中国区，启用月订阅。

| 项目 | 内容 |
|---|---|
| 时间 | **6–8 周**（含审核缓冲） |
| 工作量 | 约 **26 PD + 商业/审核 buffer** |
| 分发 | App Store 中国区 |
| 账号 | 仍不需要（纯本地；订阅靠 Apple ID 恢复） |
| 订阅 | **仅月付 ¥29.9**；前 3 张免费 |
| 合规 | App 备案、隐私政策、服务条款、订阅条款、App Store 素材、年龄分级 |
| 成功标准 | 留存/付费达到门槛；退款/投诉可控；无背景/肤色事故 |

**Phase C 新增**
- StoreKit 2 月付、恢复购买、免费额度、付费墙。
- 正式 onboarding/空状态/设置/隐私/诊断。
- 无障碍/简中/多设备矩阵、商业级 QA（把 Phase A 的 Lite WP-23/24/25 升级为完整版）。
- App 备案/隐私政策/商店素材/审核说明。
- 分阶段发布、监控、客服、回滚。

**Phase C 不做**：账号、微信/手机号、云擦除、批量、多风格、牙齿/眼睛；这些是 v2.1/v2.2。

## 3. 工期与工作量重排

| 阶段 | WP | PD | 3 名工程工期 | 交付 |
|---|---|---|---|---|
| A 自用 | 23 个 WP | 202 | **16–18 周** | 配对学习→生成成片的本地闭环 |
| B 朋友 | 3 个 WP | 22 | **4–5 周** | TestFlight + 风格卡/引导 |
| C 商业化 | 4 个 WP + buffer | 26+ | **6–8 周** | App Store + 月订阅 |
| **合计** | 30 个 WP | 250 | **26–31 周** | 正式上线 |

> 和原 24 周商业化计划相比，**总时长略长**，但：
> - 首个可用版从 24 周提前到 **16–18 周**，且核心“配对学习→生成”已闭环；
> - 先验证“自己是否真的会用、学到的风格是否真的像自己”，再投入订阅/备案/商店；
> - 如果 Phase A/B 不成立，可以停在自用/朋友阶段，不浪费商业化成本。

### 不同团队规模

| 配置 | Phase A | 到 App Store |
|---|---|---|
| 3 名工程（2 iOS + 1 图像）+ 设计/QA 兼职 | 16–18 周 | 26–31 周 |
| 2 名工程 | 24–28 周 | 34–40 周 |
| 1 人 + AI 辅助 | 32–44 周 | 44 周+ |

## 4. 对现有 30 个 WP 的阶段映射

| 阶段 | WP | 说明 |
|---|---|---|
| **A 自用** | WP-00~11、WP-12~17、WP-19、WP-21、WP-23~25（23 个） | 工程/配对/学习/工具/编辑器/导出/最小设置/质量 |
| **B 朋友** | WP-18、WP-22、WP-27（3 个） | 风格卡/引导/TestFlight |
| **C 商业化** | WP-20、WP-26、WP-28、WP-29（4 个） | 订阅/无障碍/商店备案/发布 |

**Phase A 的 Lite 调整**：
- WP-24 性能：只测自己的机型，不做完整矩阵。
- WP-25 黄金图：20–30 张授权/合成样本，不做 100 张。
- WP-23 边界态：只覆盖自用高频场景（无人脸/多人/权限/存储/中断）。
- WP-21 设置：只做删除本地数据/版本/隐私说明。
- WP-03 设计系统：只做必要组件，不做完整品牌。

> 这些 Lite 调整约省 15–20 PD；Phase A 仍按完整核心闭环 202 PD / 16–18 周估算。

## 5. 分发方式

### 5.1 自用（Phase A）

- Xcode 直接安装到自己的 iPhone。
- 免费 Apple ID 的个人签名通常 7 天过期；**建议付费 Apple Developer Program（$99/年）**，签名 1 年，省去反复重装。
- 不需要 App Store、TestFlight、App 备案。
- 不需要公开隐私政策；但照片仍只本地处理，建议自己保留一份简单说明。

### 5.2 朋友（Phase B）

- **TestFlight 内测**：
  - 内部测试员（App Store Connect 团队成员）最多 100 人，通常不需要 Beta App Review；
  - 外部测试员最多 10,000 人，需要 Beta App Review；
  - 朋友试用建议内部测试员，或小范围外部测试。
- 不需要公开 App Store 页面/订阅；TestFlight 只展示测试信息。
- 仍需遵守 Apple Developer Program/TestFlight 条款；不要上传用户照片。
- 朋友反馈用微信/问卷/访谈，不接第三方分析 SDK。

### 5.3 商业化（Phase C）

- App Store 中国区上架；App 备案、隐私政策、商店素材、IAP 审核。
- 订阅用 StoreKit 2 月付；恢复购买靠 Apple ID。
- 不做账号；保持纯本地。

### 5.4 “配置描述文件”能不能安装 App？

**不能。** iOS 配置描述文件（`.mobileconfig`）用于 Wi-Fi、VPN、证书、MDM、设备限制等，**不是 App 安装包**，不能把 `.ipa` 装到普通 iPhone 上。

正规安装方式只有：

| 方式 | 是否适合 | 说明 |
|---|---|---|
| Xcode 真机 | 自用最佳 | 免费签名通常 7 天；付费开发者账号 1 年 |
| TestFlight | 朋友试用最佳 | 内测/外测；外测需 Beta App Review |
| Ad Hoc OTA | 小范围可行但麻烦 | 付费账号、收集 UDID、100 台/年、重新签名、HTTPS manifest；**不是 `.mobileconfig`** |
| Enterprise/MDM | 仅限企业内部 | 企业证书只允许内部员工；给朋友用违反 Apple 协议，可能被吊销 |
| App Store | 商业化 | 需要审核/备案/订阅 |

网上所谓“描述文件安装 App”通常是企业证书/Ad Hoc 的 OTA 变体，或者灰色“超级签名”；存在证书吊销、隐私和合规风险，**不建议**。你的场景：

- **自用**：Xcode 直接装，付费开发者账号。
- **朋友**：TestFlight，不要用描述文件/企业证书。

## 6. 商业化前必须验证的假设

自用/朋友阶段很容易“自己觉得好用”，但不等于有人愿意付费。Phase B→C 的门槛：

| 假设 | 验证 | 通过标准 |
|---|---|---|
| 自己会用 | 4 周自用记录 | 每周 ≥3 次；单张 ≤5 分钟 |
| 朋友会持续用 | TestFlight 4 周 | ≥10 人；D7 ≥30%；每周 ≥2 次 |
| 效果自然 | 盲测/访谈 | ≥65% 偏好；背景投诉 <5% |
| 愿意付费 | 假门/预约/访谈 | ≥15% 表示愿意月付 ¥29.9 |
| 不是“友情支持” | 匿名问卷/价格测试 | 付费意愿不依赖人情 |

**未通过**：不要上 App Store/订阅；继续自用/朋友迭代，或停在免费工具。

## 8. 最终建议

**建议按三阶段走。**

- **Phase A 先做“自己每天愿意用”的本地版**：16–18 周，含配对学习闭环，不做订阅/备案/完整 onboarding。
- **Phase B 给 10–30 位朋友 TestFlight**：加 3/5/8 校准与风格学习，验证留存与自然度。
- **Phase C 再商业化**：月订阅、App Store、备案、商店素材、正式 QA。

核心架构不需要推翻；需要改的是**优先级、交付节奏和商业化的时间点**。如果 Phase A/B 不成立，停止在自用/朋友阶段，比直接做 24 周商业版更划算。
